# Review handoff contract (derived from the included example exports)

## Measured source pair

- Selection: 1,693 bytes; SHA-256 `9aebb1500a30c5feadb9ce7fa165a135031b20664ffc1be192175ce1df71721b`.
- Comparison: 35,795 bytes; SHA-256 `bae2cfbcb560d40d145ce87ee48e7ad3ac17e551505250fddcf66b32df860783`.
- The selection declares exactly that comparison byte length and digest. The original filename is a label, not a path to follow or identity check.
- Purpose label: `Dispatch evidence follow-up`. Selected records are `/records/3` (`id:MAR-014`, changed, both sides present) and `/records/4` (`id:MAR-015`, missing, current present / incoming absent). There are 10 comparison records; 8 are outside the requested scope.

## Accepted v1 inputs

The library accepts raw Buffer/Uint8Array bytes, not parsed objects or reserialized comparison text. Both files must contain unambiguous UTF-8 JSON objects. Reject malformed UTF-8, BOM, duplicate object member names, excessive nesting, non-finite numbers and numbers that cannot be represented without changing their decimal value. No trimming, normalization, coercion, pointer repair, timestamp sorting, or source/evidence fetching.

Selection requires `format: "decision-comparison-review-selection"`, numeric `version: 1`, string `purpose`, `createdAtLocalClock`, `selectionMeaning`, `sharedHistory: "unproven"`, `authentication: "unproven"`, and an integer nonnegative `selectedCount` equal to `selectedRecords.length`. Optional `reviewContext` contains string `purposeLabel` and `meaning`; retain it exactly if supplied, including an empty purpose label. No invented label when absent. `comparison` requires string `filename`, positive safe integer `bytes`, lowercase 64-hex `sha256`, string `fingerprintMeaning`, `reportVersion: 1`, and string current/incoming workspace labels.

Measure the actual comparison bytes and require BOTH length and SHA-256 to match before interpreting its report. Then require `reportVersion: 1`, `operation: "compare"`, `readOnly: true`, `complete: true`, `sharedHistory: "unproven"`, valid current/incoming sides with v1 metadata, exact matching workspace labels, and a records array. Reject invalid/incomplete/unsupported reports even for an empty selection. Report summary and side counts must agree with its records.

Each report record has a nonempty unique `groupKey`, classification `unchanged|changed|added|missing`, and explicitly present `current` and `incoming` properties. A side is either a snapshot object or null. Null means absent; an omitted property, false, empty string, or array is malformed, not an alternative absence marker. Present snapshots carry their matching groupKey and the observed fields (orderId, categories, status, note, revision, updatedAt, sourceEvidence). Extra snapshot facts are retained, not silently dropped. At least one side must be present. The four reported change flags (`statusChanged`, `noteChanged`, `decisionChanged`, `sourceEvidenceIdentityChanged`) must be booleans when both sides are present and null when one is absent. Their values are not independently derived. Classification is a supported producer-reported label, not recomputed from snapshot equality or side presence. Summary counts count those reported labels; side decision counts count present snapshots. All records, including unselected ones, receive these structural checks. The consumer does not sort, rewrite or deduplicate snapshot arrays, compare their membership, or validate evidence identities.

Each selected entry requires nonempty string `groupKey`, nonnegative safe integer `recordIndex`, canonical `jsonPointer` exactly `/records/<recordIndex>`, a matching classification and strictly boolean current/incoming presence flags. Resolve only that array index, never a key-search fallback or arbitrary object traversal. Check bounds, exact key/classification/presence agreement and reject duplicate selections. Preserve selection order.

Selected `/records/N` pointers are literal canonical array-index references. Reported change paths have a different ownership boundary: they are **opaque string labels**, not pointers for this consumer to execute. Each `changes` entry must be an object with a string `path` and own `current` and `incoming` properties containing accepted JSON values. Labels and delta values are retained exactly, including repeated labels and nulls; no decoding, lookup, normalization, target existence check, or comparison with snapshot values occurs. `sourceEvidenceChanges` must be an array; its contents are preserved as report data, not interpreted as another comparison policy. The companion producer may use occurrence-key labels such as `/sourceEvidence/revised:15/sourcePath`; this consumer neither resolves those labels nor imposes array-position semantics.

This utility verifies byte binding, supported structure and selection-to-report agreement—not the producer's comparison semantics. A structurally valid report can contain a classification, change flag or delta inconsistent with its snapshots and still be accepted if the selection agrees with the report. Such acceptance does not certify that report as correct or authentic. No snapshot-comparison or change-path-resolution implementation belongs to this consumer.

## Brief semantics

The brief retains the original purpose, optional review context, comparison byte identity and workspace/version labels. Only selected records appear, with exact complete current and incoming snapshot values plus the report record facts. The supplied report is the source of reported facts, not the copied selection labels; neither is treated as authenticated authority. JSON null remains null, empty strings remain empty, and incoming null remains explicitly absent; no synthetic incoming snapshot or guessed deletion. Markdown opens with a skim-first review brief: exact purpose label, selected record IDs, outside-scope count, review-only meaning, side-by-side-in-prose status/notes, reported changes, and compact source filename/occurrence/physical-line references. Source values use adaptive inline JSON code spans, not executable links or instructions. A clearly labeled reference appendix follows with complete selected facts and provenance as safely fenced literal JSON. Repeated status/note deltas are abbreviated only when their exact values already appear in the snapshot summary; otherwise the supplied delta values are displayed separately without substitution. This is presentation-only, not semantic validation. The original generated Markdown example is retained separately. The supplied pair still produces byte-identical JSON and revised Markdown; strict parsing, byte/selection binding and output file safety are unchanged.

Always say this is a review request only; not application, merge, approval, resolution, deletion, or authorization. Unselected records are outside scope, without implicit approval/rejection/resolution. Byte fingerprinting identifies only the supplied bytes, not authenticity, trusted-source integrity, shared history or authorization. Evidence claims remain unverified and referenced paths are never opened. Timestamps and revisions do not establish precedence.

A valid empty selection yields zero records, an explicit no-records-selected message, the original purpose/context and measured comparison identity. It does not infer that the report has no differences.

## Local interface and file safety

CommonJS library and Node CLI; Node 22+; built-ins only. CLI reads explicit selection/comparison file paths. Markdown is the default; JSON is selectable. Validate completely before writing output. Output files are created exclusively (never overwritten), so existing inputs, hard links, symlinks and existing generated outputs are protected. Output directories must already exist. Stdout is supported, but shell redirection can truncate files before Node starts: never redirect over an input. No source paths in the report are followed.
