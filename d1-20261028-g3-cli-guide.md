# Parcel labels CLI

Run these commands from the repository root with Node.js 22 or newer. No
dependencies, package scripts, or configuration changes are needed.

`d1-20261028-g3-labels-cli.js` accepts one optional input filename. Without a
filename, it reads stdin as before. It reads one complete JSON value and passes
it to the existing `parcelLabels` function. The value must be an array
of nonnegative safe integer numbers, from `0` to `9007199254740991` inclusive.
Numeric strings are not converted. JSON whitespace is allowed.

On success, exit status is **0** and stderr is empty. Nonempty batches produce
one label per line, including exactly one final newline. An empty array produces
zero stdout bytes. On malformed JSON or invalid counts, exit status is **1**,
stdout is empty, and stderr contains one concise error line. Validation finishes
before any labels are written, so even a late invalid count cannot produce
partial stdout. Element indexes in errors are zero-based.

## Help

Display a short usage message, accepted input description, and runnable example:

```sh
node d1-20261028-g3-labels-cli.js --help
```

The short form displays the same help:

```sh
node d1-20261028-g3-labels-cli.js -h
```

Both flags write help to stdout, leave stderr empty, and exit **0** without
opening an input file or reading/waiting for stdin. Help takes precedence even
when a supplied filename does not exist. Any piped input is ignored in help
mode, even if it is malformed JSON. Strings such as `"--help"` inside the JSON
remain invalid counts. The runnable stdin example printed by help is the
ordinary-input command below; help also shows the saved-file invocation.

## Saved JSON files

Pass the filename as the only positional argument. Relative paths are resolved
from the current working directory; quote paths that contain spaces, for example
`node d1-20261028-g3-labels-cli.js "parcel counts.json"`.

Here is an end-to-end example. This creation command refuses to overwrite an
existing example file:

```sh
( set -C; printf '%s\n' '[0,1,3]' > d1-20261028-g3-example-counts.json )
```

Read the saved file (exit 0; stdout is `0 items\n1 item\n3 items\n`):

```sh
node d1-20261028-g3-labels-cli.js d1-20261028-g3-example-counts.json
```

When a filename is provided, stdin is ignored and the command does not wait
for stdin to close. File input has the same JSON validation, label formatting,
empty-array behavior, and all-or-nothing output as stdin. An empty **file** is
invalid JSON; a file containing `[]` succeeds without output.

Missing or unreadable files exit **1**, write no stdout, and report the quoted
filename and reason on stderr. For example, if the following path does not exist:

```sh
node d1-20261028-g3-labels-cli.js d1-20261028-g3-missing-counts.json
```

The error is `labels: cannot read input file "d1-20261028-g3-missing-counts.json": file not found`.
Files without read permission report `permission denied`; a directory reports
`path is a directory`. There is no fallback to stdin if reading or validating
the file fails. More than one filename is rejected with an error and exit 1.

## Successful stdin commands

Ordinary input (exit 0; stdout is `0 items\n1 item\n3 items\n`):

```sh
node d1-20261028-g3-labels-cli.js <<'JSON'
[0,1,3]
JSON
```

Empty input array (exit 0; no output on either stream):

```sh
node d1-20261028-g3-labels-cli.js <<'JSON'
[]
JSON
```

Whitespace around JSON (exit 0; stdout is `1 item\n0 items\n`):

```sh
node d1-20261028-g3-labels-cli.js <<'JSON'

  [1, 0]

JSON
```

## Error commands

Each command below exits 1 and writes **no stdout**. The expected stderr line
is shown above each command. To inspect the status in a POSIX shell, run
`echo "$?"` immediately after the command (without `set -e`).

Malformed JSON: `labels: invalid JSON; expected an array of nonnegative safe integers`

```sh
node d1-20261028-g3-labels-cli.js <<'JSON'
[0,1,
JSON
```

Scalar JSON: `labels: counts must be an array`

```sh
node d1-20261028-g3-labels-cli.js <<'JSON'
1
JSON
```

A later invalid element: `labels: counts[2] must be a finite integer number`

```sh
node d1-20261028-g3-labels-cli.js <<'JSON'
[0,1,"2"]
JSON
```

A negative integer: `labels: counts[1] must be a nonnegative safe integer`

```sh
node d1-20261028-g3-labels-cli.js <<'JSON'
[0,-1]
JSON
```

An unsafe integer: `labels: counts[0] must be a nonnegative safe integer`

```sh
node d1-20261028-g3-labels-cli.js <<'JSON'
[9007199254740992]
JSON
```

Fractions, non-number elements, and non-finite parsed numbers (for example,
`1e309`) also fail validation. Empty stdin is malformed JSON, not an empty batch.

## Test commands

Focused integration tests launch the CLI in real Node subprocesses and check
exit status, stdout, and stderr independently. They cover both help flags with
empty, valid, and malformed stdin, verify that help exits while stdin remains
open, and retain all normal-input and validation checks. The same valid and
invalid inputs are exercised through files. Additional checks cover relative
paths with spaces, file input without waiting for stdin, missing/unreadable
files, extra filenames, and help taking precedence over missing files. Temporary
fixtures are cleaned up after tests. The POSIX permission-denied check uses the
OS temporary directory (mounted worktrees may ignore permission bits) and is
skipped on Windows or when running as root.

```sh
node --test d1-20261028-g3-labels-cli.test.js
```

Run all tests, including the existing helper and batch tests:

```sh
node --test
```

The tests use the existing `node:test` runner, `node:assert/strict`, and built-in
`node:child_process`. There are no declared build/lint checks in this project.
